# Scene-camera eye tracking

Open `/trial/scene-camera-eye-tracking`. This public route runs locally in the browser with one eye camera and one outward-facing scene camera. `/trial` retains screen calibration.

```sh
cd frontend
bun install --frozen-lockfile
bun run dev --port 4014
```

For a production preview, run `bun run build` followed by `bun run --cwd apps/web preview --port 4014`. The dev/build commands regenerate the classic hand worker and matching WASM files from the pinned MediaPipe package. The hand model is included in the repository; no CDN/model download is required by a wearer.

## Setup

1. Choose the eye camera, frame the eye, and build/lock the eye model. Both v2 manual and automatic tracker formats remain available.
2. Connect a different outward-facing USB device or a network stream. Both eye and scene cameras use the same local relay at `http://127.0.0.1:4022`; start it with `bun run camera-relay` from `frontend/apps/web`. Enter the camera's exact HTTP(S) MJPEG or browser-playable video URL, such as `http://esp32.local/stream` or `http://192.168.1.90:81/stream`. The app preserves the supplied host, port and path. The standard ESP32 CameraWebServer commonly uses port 81, but a working URL does not need to be rewritten. The camera itself does not need CORS headers or HTTPS. The relay resolves the camera on the wearer's machine and supplies the browser-readable response. It currently accepts `.local` hostnames and private LAN IP addresses, not arbitrary public streams, credential-bearing URLs or RTSP. A hosted website still requires the relay on the wearer's machine, its exact website origin in `GAZE_CAMERA_RELAY_ALLOWED_ORIGINS`, and any browser-required local-network permission. This does not bypass browser security restrictions.
3. Mount both cameras rigidly on the headset. Preview controls can rotate and mirror either camera. Coordinates use the displayed scene axes: x increases rightward and y downward. The preview preserves the full frame.
4. Start finger calibration. Look at your **physical index fingertip**, place it in the preview ring, press **Space** to lock the point, and hold steady. Watching the finger's screen image would provide the wrong fixation reference. MediaPipe draws all 21 landmarks and highlights index landmark 8. The eye preview shows pupil confidence and gaze readiness alongside the scene.
5. The collector settles for 300 ms, then needs at least 20 distinct eye/scene pairs and 800 ms of observed steady time. A hand detection or frame gap of up to three seconds pauses an armed hold and dims the last outline. Only fresh, paired observations count; cached positions and missing-frame time do not. Brief weak pupil evidence pauses for up to 350 ms. A blink, sustained weak/missing eye evidence, real finger/gaze movement, or a longer hand gap clears the unfinished hold. Left/right hand-label jitter alone does not reset it. Optional sounds let you keep looking at the physical fingertip: a low tone when stable capture starts, a quiet continuous tone while fresh samples fill the bar, a 180 ms buzzer when tracking is interrupted, and a rising double tone when the point is saved. The capture tone stops on pause, cancellation, mute or completion. Its 250 ms watchdog is renewed only by fresh paired samples, so a stalled pipeline or duplicate repaint cannot keep it playing. Repeated interruptions are limited to one buzzer per second. The speaker icon remembers its mute setting and explains the sounds on hover. All nine locations and broad horizontal/vertical coverage are required.
6. Hand and marker calibration automatically start a five-point fresh accuracy check. This reports normalized image RMS and native-scene pixel RMS; the fitting score alone is not an independent accuracy measurement. Passing it opens live gaze automatically. A failed check keeps an unverified preview and its diagnostics available.

## Three calibration methods

Choose **Hand**, **Marker**, or **One point** in the calibration card. The choice is remembered locally. These methods are independent of the manual/automatic eye-model choice.

- **Hand:** the existing nine physical fingertip locations and five separate accuracy checks. Space locks each point. Saved progress stays full; brief movement or detection gaps pause without erasing valid samples. Sustained movement clears only the unfinished hold.
- **Marker:** the eye camera sits on the left, a large circular marker in the middle, and the scene camera on the right. Aim the scene camera at this page and look continuously at the marker's red center. Slowly move your head to bring that stationary reference through different scene-image regions; pause for each capture tone. The detected center supplies real camera-image coordinates, and nine regions plus five new checks capture automatically. The size icons adjust the target before capture; its center and size stay fixed throughout the hold. No download or separate application is needed. The download icon still offers an optional [printed copy](gaze-core-calibration-marker.svg); use matte white paper at your working distance. Reduce display brightness if the camera sees glare.
- **One point:** look at your physical index fingertip anywhere in the scene and press Space once. One stable hold opens live gaze immediately. Reanchoring a previously checked mapping preserves its shape; otherwise an adjustable nominal projection estimates the rest of the field. First correct both camera views with their rotation/mirror controls: the eye camera faces the eye and the scene camera faces outward. The adjusted views are the coordinate frames used for calibration. Wearer-right moves the front-facing pupil left and the scene gaze right; vertical directions agree. Camera adjustments are not undone or applied a second time. X/Y gains adjust sensitivity; X/Y offsets shift the dot. One fixation cannot independently determine physical camera mounting, scale, perspective or accuracy. The dashed amber dot and exported `estimated` flag identify this experimental mode. Optional **Check accuracy** still measures five new locations without changing the mapping.

Marker detection runs in a dedicated latest-frame OpenCV worker. The broad black ring, white gap and black center disc remain legible with fewer pixels than the old checker pattern. Gaussian denoising, histogram and local adaptive thresholds handle exposure changes and uneven illumination. Nested-ellipse shape, band ratios and local contrast checks reject ordinary circles, clipping, occlusion and ambiguous references. The small center disc supplies the fixation location, reducing the perspective bias of the outer ellipse. This is a 2D center estimate, not 3D pose recovery.

The worker preserves up to 960 pixels on the image's longest side and processes only the newest waiting frame. It never invents positions for missing or stale detections. A clearly smaller recursive preview copy cannot displace the dominant reference; similar-sized candidates are rejected. After acquisition, an abrupt shrink to under 40% of the previous projected area is rejected so a miniature preview cannot take over during loss. Gradual size changes remain measurable; a camera source or image-size change resets this scale guard. During same-page calibration the scene preview displays the detected outline in place of its black-and-white pattern, preventing that preview from becoming another optical target. Detector input and raw recordings remain untouched. Hand and marker reference extraction both feed `SceneSession.observeReference`, then the same timestamp pairing, stable-hold collector, `inspectSceneCalibration` fitter and `validateSceneCalibration` accuracy check. The reference detector and manual/automatic locking differ; the mapping mathematics do not.

## Timing and mapping

Both pipelines use `performance.now()` timestamps. Pairing allows at most 100 ms mismatch after the selected relative delay adjustment. Timestamp histories are limited to three seconds. The current scene source must stay fresh within 250 ms. Pairing allows the intentionally delayed side an additional configured offset: negative delays retain earlier hand/scene observations until the later eye evidence arrives; positive delays use earlier eye evidence. Duplicate pupil evidence does not create fresh measurement rows.

Hand drawing has light time-based smoothing that relaxes during motion and resets on reacquisition, source changes or confirmed fast movement. A large sudden landmark jump must be confirmed by a second fresh matching frame; an isolated spike becomes missing evidence and pauses collection. Jump limits scale with the observed palm size. Accepted calibration and log coordinates retain the raw detector values, with their original frame timestamps. Preview smoothing cannot supply samples or increase measured accuracy. MediaPipe detection gaps remain gaps.

A positive **Scene arrival delay relative to eye** means the scene stream arrives later. For example, +100 ms pairs a scene received at 1000 ms with eye evidence near 900 ms. A negative value means the eye stream arrives later; pairing waits for that evidence and records the corresponding historical scene frame ID and timestamp. This is a manually supplied compensation for transport/decode delay, not hardware synchronization. Compare fresh accuracy checks at stable working distances when tuning it; a fixed compensation cannot correct variable network jitter.

The mapping uses gaze features from the locked eye model. It compares affine, projective and quadratic candidates using whole-location leave-one-out checks, selecting a more complex mapping only for at least 10% improvement. The projective candidate handles perspective geometry between gaze slopes and a fixed calibration plane; it rejects singular fits and a projective horizon within the sampled feature rectangle. Training fits with normalized RMS over 0.025 or a worst-point error over 0.05 are rejected. Leaving out a corner extrapolates beyond the remaining coverage, so that diagnostic alone no longer rejects a good fit. The separate fresh accuracy thresholds remain unchanged. These thresholds are initial software guardrails; measured accuracy still depends on the headset, optics, fixation and synchronization.

If the fit fails its error limits, calibration stops with diagnostics and offers an explicit repeat of one location while retaining the other eight points. It does not automatically loop through corner retries. The app refits after the chosen replacement is saved. Structural failures such as collapsed eye features instead report the eye-model or coverage problem. The diagnostic download icon saves the failed holds, raw paired observations and per-point errors as local JSON. No diagnostic data is transmitted.

The mapping survives browser resizing and head motion while the eye/camera alignment stays fixed. Changes to sources, frame dimensions, eye setup or delay invalidate it. After headset slippage, use **Recalibrate / headset moved**. Depth changes can introduce monocular parallax error; calibrate and validate near your working distance. Hand-relative MediaPipe world landmarks do not provide absolute scene-camera distance.

Live gaze works after the hand leaves the view. Pupil or scene loss suppresses the dot; outside-view coordinates remain outside-view in exported data rather than being clamped to the edges. Predictions outside the sampled bounding coverage are marked as extrapolated.

## Calibration points and live offset

One stationary fingertip fixation supplies a two-axis translation, but cannot establish the mapping's scale, rotation or perspective across the scene. Hand and marker methods retain nine calibration locations and five separate validation locations; one-point mode exposes an estimate for experimentation. Those counts are this app's coverage and accuracy checks, not a universal eye-tracker requirement. A five-position quick mode (center plus inset corners, with additional positions if fresh checks need them) has been discussed but is not implemented. The present coverage guard requires nine regions; a five-position mode would also need a simpler mapping and matching collection/validation rules. Pupil's [single-marker procedure](https://docs.pupil-labs.com/core/software/pupil-capture/#single-marker-calibration-choreography) still gathers many gaze angles while the wearer moves their head and keeps looking at one physical marker.

For integration into another working branch, see the [worktree-v4 merge handoff](worktree-v4-merge-handoff.md), including preservation requirements and the uncommitted source inventory.

After calibration, **Live gaze → Offset · px** adjusts X and Y in native scene-camera pixels. Positive X moves right; positive Y moves down. The reset icon restores both to zero. A constant offset applies to the live dot, trace, gaze log and heatmap; raw videos remain free of overlays. It cannot fix errors that vary with gaze direction or depth. The old trace clears when the offset changes, and new calibration or camera/setup changes reset the offset.

After an adjustment, the previous accuracy result is labeled **Previous accuracy check**. The shifted dot remains visible as an unverified preview until a fresh check passes at that offset. Experimental one-point recordings remain available and carry the estimate label. **Check accuracy** tests the corrected mapping at five fresh locations and records the offset used for that test. Offset controls are disabled during recording; each JSON session stores its applied normalized `gazeOffset` and the validation's independently measured `offset`. A programmatic offset change finalizes the recording so a session never mixes offset coordinate systems.

A failed accuracy check keeps the fitted mapping and shows a dashed amber **Unverified preview** alongside native-pixel RMS, worst error, and five per-point errors. Its fresh predictions remain `valid: false`, so they cannot become validated recording or heatmap data. Stale frames and pupil loss still suppress the preview. X/Y offset controls remain available at this step. When a translation halves the measured RMS and brings every location within the existing error limits, **Try offset & check** applies that proposed translation and collects five new validation holds; the samples used to propose it cannot themselves count as an independent pass. When only one location fails, **Repeat point** keeps the mapping and the other four checks. An offset change disables that reuse. **Check again** always collects five new holds while keeping the nine-point mapping. The download icon saves the mapping, raw validation holds, signed per-point errors, delay and offsets locally for diagnosis. Spatially varying errors do not receive a constant-offset recommendation.

## Local recording and exports

**Start recording / data log** records an overlay-free scene video and coordinate log. USB video uses an owned clone of the camera track. Network/MJPEG video is a browser re-encode of a separate raw canvas. Optional eye video is a re-encode of the raw eye preview canvas. Hand skeletons, gaze dots, traces and heatmaps are never baked into those raw recordings.

Each session is bounded to ten minutes, 18,000 coordinate rows, 18,000 hand observations and 128 MiB of combined video (64 MiB per video when recording both). A camera failure, setup/calibration change, codec failure or limit finalizes available data. Completed downloads remain available until cleared or replaced. If video capture is unsupported, coordinate logging remains usable. Leaving the route stops capture; save downloads before closing it.

- **Raw scene/eye video:** browser-selected MP4 or WebM; the filename matches the actual MIME type.
- **Gaze CSV:** elapsed session milliseconds, browser timestamps, eye/scene frame IDs and timestamps, confidence, normalized/pixel coordinates, validity, loss reason, extrapolation and estimated-quality flags.
- **Session JSON:** calibration pairs and holds, independent validation and its offset, applied gaze offset, camera/settings/model metadata, delay, time origin, video start offsets, gaze measurements and full image/hand-relative world landmarks.
- **Heatmap PNG:** dwell-weighted image-space density over the last raw scene frame. Invalid/out-of-frame intervals and gaps over 250 ms contribute no dwell. It accumulates camera-image locations as the headset moves; it does not identify or register physical objects across motion.

Video timestamps and gaze timestamps share a browser clock but are not guaranteed frame-exact. JSON records each encoder's start offset from the coordinate-session origin. Test alignment with your cameras before using exports for timing-sensitive analysis.

## Research basis

The circular reference and nested-ellipse checks follow the approach in [Pupil Core's circle detector](https://github.com/pupil-labs/pupil/blob/master/pupil_src/shared_modules/circle_detector.py). [OpenCV's thresholding guide](https://docs.opencv.org/4.13.0/d7/d4d/tutorial_py_thresholding.html) describes histogram and adaptive thresholds for global and local lighting variation. The detector uses the app's existing pinned OpenCV runtime and this app's own broad-ring proportions and quality checks.

[Bâce, Staal and Sörös's ETRA fingertip-calibration paper](https://vs.inf.ethz.ch/publ/papers/mbace_etra2018.pdf) and [published Pupil plugin](https://github.com/mihaibace/fingertip-calibration) demonstrate physical-fingertip fixation as a calibration reference. [Pupil's guide](https://docs.pupil-labs.com/core/software/pupil-capture/#gaze-mapping-and-accuracy) emphasizes field-of-view coverage, separate accuracy tests and depth-dependent parallax. [OpenCV's homography guide](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html) explains projective relationships involving a plane. [Google's web guide](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js) documents the hand landmarks and recommends worker inference to avoid blocking the interface. The current feature combines these ideas with the existing v2 gaze model; it does not implement Pupil's 3D bundle adjustment or infer hardware accuracy from those studies.

## Verification and hardware check

Run `bun test`, `bun run typecheck`, `bun run lint`, and `bun run build` from `frontend`. Tests cover calibration quality, pairing, loss, independent camera lifecycle, worker cleanup, recording failure, export formats and heatmap dwell.

Before relying on a real headset, validate a second set of physical fixations at intended depths, compare both manual/auto modes, test stream jitter and disconnect/reconnect, check video/coordinate offsets with an observable event, and repeat after taking off/refitting the headset. Automated tests and browser fixtures cannot measure actual gaze accuracy.

## Reproducible browser smoke fixture

After `bun run build`, run `bun tests/scene-eye-tracking/prepare-browser-fixture.ts` from `frontend`, then `bun run --cwd apps/web preview --host 127.0.0.1 --port 4014`. Open `/scene-fixture.html`. This disposable page uses synthetic camera, pupil and hand data; it does not request camera access or modify the production route.

Use **Test real MediaPipe worker** to load the production worker/WASM/model and run inference on a synthetic image. Connect the synthetic scene camera, start finger calibration and then sweep nine regions. Open live gaze, record/stop, export CSV/JSON/PNG, and toggle hand/pupil loss. A new production build removes the fixture page. Use **Inspect completed raw video** to check the finalized blob type, size and decoded dimensions directly, even when the browser automation environment does not expose downloads. These checks prove browser integration, not hardware accuracy.
